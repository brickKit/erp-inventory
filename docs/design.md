# erp/inventory 的设计

本页写这个组件为什么这样设计：术语、拥有的数据、规则、命令与事件、依赖、实现状态与未决问题。写给要修改它的人与 AI。怎样使用、部署与配置在 `BRICKKIT.md`；代码在哪、怎样构建与测试在 `AGENTS.md`。跨组件的规则在装配项目：预占分支的状态、命令与恢复在协议 04（本组件是参与方），计价序号在协议 05b，库存流水序号与关账在协议 06，增量事实的去重与补取在协议 05 的共同规则，提交后编号在协议 02；可用量的不变量与分支怎样落到余额上在 [rules/availability.md](rules/availability.md)。

## 边界

物理库存变动的唯一写入者：仓库、流水、余额、预占分支。销售与采购经本组件的契约请求变动，不自己维护余额（D45）。

| 不在这里 | 归谁 |
| --- | --- |
| 存货的成本与计价 | `erp/costing`（按计价序号读流水；库存与财务之间没有事件） |
| 订单、交货的业务状态 | `erp/sales`（它是预占的协调者，本组件是参与方） |
| 复杂的仓库作业（波次、拣货、复核） | `erp/warehouse`（远期，经本组件的契约出入库） |
| 产品的追踪政策、单位与换算 | `mdm/product` |
| 法人 | `mdm/org` |

## 术语

| 业务叫法 | 定义 | 代码标识符 |
| --- | --- | --- |
| 仓库与库位 | 仓库属于一个法人；库位是仓库内的位置（以后） | `warehouse`；`location`（以后） |
| 库存维度 | 产品、仓库、库位、批次、序列号、库存状态、货主；本版只有产品、仓库、批次、序列号（货主固定为本企业，库存状态都是可用） | `product_id`、`warehouse_id`、`batch`、`serial` |
| 流水 | 一次不可修改的库存变动，数量用产品的基本单位；更正以反向流水表达。类型：入库、出库、调拨、调整、期初、销售退货、采购退货；本版只有前两种 | `movement`；类型 `receipt`、`issue`（以后 `transfer`、`adjustment`、`opening`、`sales_return`、`purchase_return`） |
| 在库、已预占、可用 | 在库是流水的累计；已预占是 `held` 与 `committed` 分支未消耗的部分；可用 = 在库 − 已预占 | `on_hand`、`reserved`、`available` |
| 预占分支 | 一张订单一次确认在本组件的一条分支，含该订单的全部实物明细（协议 04） | `branch`；状态 `held`、`committed`、`consumed`、`released`、`expired`、`rejected`、`cancelled` |
| 消耗 | 出库在同一个事务里扣减分支的数量，按消耗身份幂等 | `consumption_id` |
| 库存流水序号 | 每条流水在本组件范围内的连续序号，关账时成本组件按它补取与封存 | `inventory_seq` |
| 序号高点 | 成本组件关账封存前请求的库存流水序号上限：库存写一条标记行并锁内编号后返回；标记行不是流水，成本组件跳过它（协议 06，以后） | — |
| 计价序号 | 每条流水在“产品 + 法人”内的连续序号，成本组件按它计价；与成本组件是否安装无关 | `valuation_seq` |
| 盘点 | 盘点单记录实盘数，差异经审批形成调整流水（以后） | — |

## 拥有的数据

| 表 | 内容 | 终态与保留 |
| --- | --- | --- |
| `warehouse` | 仓库：法人、代码（法人内唯一）、名称、状态 | 停用，不删除 |
| `stock_position` | 每个“产品 + 仓库”的在库与已预占（可用量的权威行，加锁的对象） | 随流水与分支变化 |
| `stock_lot` | 批次追踪产品每个“产品 + 仓库 + 批次”的在库，按入库先后 | 同上 |
| `stock_serial` | 序列号追踪产品每个序列号的所在仓库与是否在库 | 出库后保留，标记不在库 |
| `movement` | 流水：类型、产品、仓库、批次或序列号、数量、法人、业务日期、来源参考（收货行、分支与消耗身份）、两个序号 | 不可修改；本版不删除（协议 11 的转层以后做） |
| `branch`、`branch_line` | 预占分支与它的明细（产品、仓库、数量、已消耗）、暂存期限、修订、不足原因；墓碑也是分支行 | 终态保留，作幂等与墓碑的依据 |
| `consumption` | 消耗记录（消耗身份 → 分支、流水） | 永久 |
| `seq_counter` | 两条序列的编号计数（库存范围一行，“产品 + 法人”各一行） | — |

以后还有：库位、库存状态与货主维度、盘点单、序号高点的标记行。

## 规则

不变量与分支怎样落到余额上的细则在 [rules/availability.md](rules/availability.md)。要点：

- 可用 = 在库 − 已预占 ≥ 0，不超卖。预占、确认、取消、消耗、出库都在 `stock_position` 行上加锁裁决。
- 一条分支的全部明细在一个本地事务中全部占住或全部拒绝；多行加锁按“产品 + 仓库”的固定顺序（RS16）。
- 分支的状态迁移、幂等（同身份同内容返回已有结果，不同内容冲突拒绝）、墓碑、暂存期限、“已到期不能确认复活”、“确认占用没有自动到期”全部照协议 04 的状态迁移表。
- 出库带分支身份时，在同一个事务里消耗分支（RS19）；出库数量不超过分支的剩余。不带分支的出库（本版没有这种入口）要检查可用量。
- 批次追踪产品出库时，没指定批次就按入库先后（先进先出）分配，分配策略是替换点；序列号追踪产品出库必须指定序列号，序列号必须存在、在库、在这个仓库。
- 流水不可修改。流水提交时不带序号；提交之后由编号事务按协议 02 第 2 步的做法锁内连续编号：先编库存流水序号，再按“产品 + 法人”编计价序号，流水事件在计价编号的事务里写进发件表，所以总带着两个序号。出入库提交后立刻编一次，失败或遗漏由每秒一次的单例工作项补上（实现时定）。
- 入库的数量与单位：契约里的数量是产品的基本单位，十进制字符串，按单位的小数位校验，不经浮点。
- 倒填流水（业务日期早于今天）的限制是库存自己的业务规则；会计上的迟到由成本组件顺延到下一期（协议 06），库存不看会计期间。
- 调整需要审批或权限（以后）。

| --- | --- | --- |

| 序号高点的读取与按序号补取（协议 06） | 系统面，只对成本组件开放 | 以后 |
| 调拨；调整（需审批或权限）；盘点 | 用户面 | 以后（契约已有调拨与调整的路径：`erp.inventory.movement.create`、`erp.inventory.adjustment.create`） |

## 事件

流 `erp.inventory`：

- 流水 `erp.inventory_movement.recorded.v1`：不可遗漏的增量事实（协议 05 的共同规则），带事实身份、库存流水序号与计价序号；在编号事务里进发件表，所以总带着两个序号；供成本组件与产品（已有流水）。
- 余额 `erp.stock_position.changed.v1`：可覆盖的状态事件（产品 + 仓库的在库、已预占、可用）。
- 预占分支 `erp.inventory_branch.changed.v1`：可覆盖的状态事件。
- 仓库 `erp.warehouse.changed.v1`：完整状态事件。

## 依赖

- `mdm/product`（必需）：入库与预占时取产品的种类、基本单位与追踪政策（同步的批量读取；服务与非库存物品拒绝）；入库后通知它“已有流水”（产品订阅本组件的流水事件，协议在产品一侧）。
- `mdm/org`（必需）：仓库所属的法人存在且启用。
- 身份、授权（必需）；`infra/audit`（可选）。

下游（调用或消费本组件，不在 `component.yaml` 声明）：

- `infra/workflow`（以后）：调整的审批；缺时在本组件页面中处理。
- `erp/sales`、`erp/purchase`：经契约预占、出入库。
- `erp/costing`：读流水与两个序号；缺时流水照常带计价序号，只是没有成本计算。
- `erp/warehouse`：经库存契约执行作业；缺时由简单操作直接出入库。

## 实现状态

实验第 7 步的范围：仓库、入库与出库流水、余额与可用量、预占分支的预占、确认、取消、查询、消耗，流水与余额的事件，两条序列的提交后编号。答“能力不支持”的：调拨、调整、盘点、库位、期初流水与期初分支、退货入库、复杂仓储的作业、分支的调整（订单修订）、序号高点与补取（协议 06）。

## 部署与替换

写热点在 `stock_position` 行；需要时单跑并单独分配数据库资源（协议 17 的热点处理）。不能整体替换为另一套余额权威；分配与出库策略（先进先出、按批次到期）是替换点。适用协议 01、02、04、05（退货入库）、05b（计价序号）、11（流水可转层）、13、14、16、17、安全 01–09；不是关账参与方（成本组件代理，协议 06）。
