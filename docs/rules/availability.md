# 可用量与预占分支

本页是库存的可用量不变量，以及协议 04 的分支命令怎样落到余额上：每个命令改哪几行、加什么锁、在什么条件下拒绝。测试按本页的表写。分支的状态迁移本身照协议 04，这里不重复。

## 不变量

对每个“产品 + 仓库”：

```text
在库 on_hand = Σ 入库数量 − Σ 出库数量            ≥ 0
已预占 reserved = Σ（held 与 committed 分支在这个产品 + 仓库上的明细数量 − 已消耗）
可用 available = on_hand − reserved              ≥ 0
```

`on_hand` 与 `reserved` 都存在 `stock_position` 的同一行上，任何改变它们的事务都先锁这一行（`SELECT … FOR UPDATE`）；一个事务锁多行时，按（产品身份，仓库身份）升序加锁，避免两个事务以相反顺序锁同一批行而死锁（RS16）。

## 每个命令改什么

| 命令 | 锁 | 检查 | 写 | 拒绝时 |
| --- | --- | --- | --- | --- |
| 预占（新分支） | 分支身份的唯一键；明细涉及的全部 `stock_position` 行 | 每一行 `available ≥ 明细数量` | 分支 `held`（暂存期限 = 现在 + 参数）；每行 `reserved += 数量` | 任一行不足：分支 `rejected`，记缺的产品与仓库，`reserved` 不变 |
| 预占（分支已在） | 分支行 | 内容相同？ | — | 内容不同：冲突（RS17）；内容相同：返回已有状态（含 `cancelled` 墓碑：迟到的预占被拒，RS04） |
| 确认 | 分支行 | `held` 且未到期 | `committed`，记确认时间 | `expired`、`released`、`cancelled`：返回该状态，不复活 |
| 取消（分支已在） | 分支行；明细的 `stock_position` 行 | 状态是 `held` 或 `committed` | `released`；每行 `reserved −= 未消耗的数量` | 终态：返回该状态 |
| 取消（分支不在） | 分支身份的唯一键 | — | `cancelled` 墓碑 | — |
| 暂存到期（工作项） | 分支行；明细的 `stock_position` 行（每个分支一个事务：一个事务里释放多个分支会把各分支的余额行累在一起，打乱全局的加锁顺序） | 仍是 `held` 且已过期限 | `expired`；释放 `reserved` | 已被确认或取消：不动（与确认在同一行上原子裁决） |
| 出库并消耗 | 消耗身份的唯一键；分支行；明细的 `stock_position` 行（及批次、序列号行） | 分支 `committed`；出库数量 ≤ 该明细的剩余；批次或序列号在库 | 流水（`issue`，带分支与消耗身份）；`on_hand −= 数量`；`reserved −= 数量`；明细的已消耗 += 数量；剩余为零时分支 `consumed` | 消耗身份已用过：返回原结果（同内容）或冲突（不同内容）；分支不是 `committed`、数量超过剩余、批次不足、序列号不存在或不在库或不在这个仓库、序列号产品没指定序列号：整笔拒绝（不写任何流水），回答原因与出问题的明细；分支不变，调用方改了再出 |
| 入库 | 入库幂等键；`stock_position` 行（及批次、序列号行） | 产品是库存商品；序列号不重复在库 | 流水（`receipt`）；`on_hand += 数量` | — |

出库同时减 `on_hand` 与 `reserved`，所以出库前后 `available` 不变：占住的数量被实际发出，没有释放给别人。

## 批次与序列号

| 追踪政策 | 预占 | 出库 |
| --- | --- | --- |
| 不追踪 | 产品 + 仓库 | 产品 + 仓库 |
| 批次 | 产品 + 仓库（不指定批次） | 指定批次，或按入库先后分配（批次号第一次入库的系统时间，不是业务日期）；所选批次的 `stock_lot.on_hand` 足够 |
| 序列号 | 产品 + 仓库（数量是件数） | 必须逐个指定序列号；每个序列号存在、在库、在这个仓库；出库后标记不在库 |

批次与序列号在出库时分配，不在预占时（协议 04 待定的“预占阶段还是拣货阶段分配”，本组件定为出库时）；所以预占成功、出库时批次或序列号不够的情形存在，出库被拒，分支保留，由仓库调整后重新出库。

## 编号

流水在出入库的事务里不编号；提交之后由编号事务按协议 02 第 2 步的做法锁住计数行，选出可见、尚未编号的流水，按插入顺序编连续的序号，并在同一个事务里写流水事件的发件行：

| 序列 | 计数行 | 用途 |
| --- | --- | --- |
| 库存流水序号 | 本组件一行 | 关账时成本组件的高点与补取（协议 06） |
| 计价序号 | 每个“产品 + 法人”一行 | 成本组件的计价顺序（协议 05b） |

两条序列在两个编号事务中分配，同一产品的两条流水在两条序列中的先后可以不同。
